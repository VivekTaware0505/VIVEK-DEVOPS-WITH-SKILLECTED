
# ==========================================
# LINUX SYSTEM MONITORING
# ==========================================

# CPU monitoring
top

# Install htop
sudo apt install htop

# Run htop
htop

# CPU information
nproc
lscpu

# Load average
uptime
cat /proc/loadavg

# Top CPU processes
ps aux --sort=-%cpu | head

# Top memory processes
ps aux --sort=-%mem | head

# Memory usage
free -h

# Memory information
cat /proc/meminfo

# Swap information
swapon --show

# Disk usage
df -h

# Directory sizes
du -sh /var/*
du -sh ./*

# Find large files
sudo find / -type f -size +500M -exec ls -lh {} \; 2>/dev/null

# Install sysstat
sudo apt install sysstat

# Disk I/O
iostat

# Detailed disk I/O
iostat -xz 1

# Virtual memory statistics
vmstat

# Continuous vmstat
vmstat 1

# Network statistics
ip -s link

# Socket statistics
ss -s

# Listening ports
sudo ss -tulpn

# Network activity
sar -n DEV 1

# List processes
ps aux

# Find process
pgrep nginx

# Process details
ps -fp PID

# Running services
systemctl --type=service --state=running

# Service status
systemctl status nginx

# Check service
systemctl is-active nginx

# Check boot status
systemctl is-enabled nginx

# System logs
journalctl -n 50

# Follow logs
journalctl -f

# Follow service logs
journalctl -u nginx -f

# Today's logs
journalctl --since today

Interview Questions
1. What is system monitoring?
Monitoring CPU, memory, disk, network, processes and services to determine system health.
2. top vs htop?
Both monitor processes and system resources. htop provides a more interactive interface.
3. What does free -h show?
Memory and swap usage in human-readable form.
4. What does df -h show?
Filesystem disk-space usage.
5. df vs du?
df → filesystem available/used space
du → space consumed by files/directories
6. What does iostat monitor?
CPU and disk I/O statistics.
7. What does vmstat monitor?
Processes, memory, paging, block I/O, interrupts and CPU statistics.
8. What does ss do?
Displays socket/network connection information.
9. How do you monitor a service's logs?
journalctl -u service-name -f
10. How would you troubleshoot a slow Linux server?
A good basic sequence is:
CPU
 ↓
Memory
 ↓
Disk space
 ↓
Disk I/O
 ↓
Network
 ↓
Processes
 ↓
Logs
