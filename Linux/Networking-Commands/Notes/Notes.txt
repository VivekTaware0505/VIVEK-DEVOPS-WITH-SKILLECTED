Linux Networking Basics
A Linux server communicates through:
Application
    ↓
Network
    ↓
Network Interface
    ↓
IP Address
    ↓
Gateway
    ↓
Internet / Other Server
Important things to troubleshoot:
1. Interface
2. IP address
3. Subnet
4. Gateway
5. DNS
6. Routes
7. Ports
8. Firewall
9. Application
2. Check Network Interfaces
The most important modern command:
ip a
or:
ip addr
Example:
2: eth0:
    inet 192.168.1.20/24
Here:
192.168.1.20 = IP address
/24          = subnet
eth0         = network interface
Show interfaces only
ip link
Show a specific interface
ip addr show eth0
Bring interface up
sudo ip link set eth0 up
Bring interface down
sudo ip link set eth0 down
⚠️ Don't bring down the interface you're currently using remotely.
3. Find Your IP Address
Simple:
hostname -I
Detailed:
ip a
Example:
192.168.1.20
Important correction
On Ubuntu/Linux:
ipconfig
is not the normal command.
That's mainly associated with Windows.
Linux uses:
ip a
4. Check Default Gateway
Run:
ip route
Example:
default via 192.168.1.1 dev eth0
Meaning:
default
   ↓
192.168.1.1
   ↓
eth0
The default gateway is normally the router used to reach networks outside your local subnet.
5. Routing Table
Show routing table:
ip route
More specifically:
ip route show
Example:
default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0
You can ask Linux:
Which route will you use to reach this IP?

ip route get 8.8.8.8
This is a very useful troubleshooting command.
6. Test Connectivity with ping
Basic:
ping 8.8.8.8
Stop with:
CTRL + C
Limit packets:
ping -c 4 8.8.8.8
Test your gateway:
ping -c 4 192.168.1.1
Test another server:
ping -c 4 192.168.1.100
What does ping tell you?
It can help determine whether packets are reaching the destination and whether replies are returning.
But:
A failed ping does not always mean the server is unreachable.

ICMP may simply be blocked.
7. Troubleshooting Sequence
Suppose you cannot access the internet.
Don't randomly run commands.
Use:
1. Interface?
       ↓
2. IP address?
       ↓
3. Gateway?
       ↓
4. Gateway reachable?
       ↓
5. Internet IP reachable?
       ↓
6. DNS working?
       ↓
7. Application port reachable?
Example:
ip a
Then:
ip route
Then:
ping -c 4 192.168.1.1
Then:
ping -c 4 8.8.8.8
Then:
ping -c 4 google.com
This sequence helps identify where the problem is.
8. DNS Troubleshooting
DNS converts:
google.com
into an IP address.
Check DNS resolution:
getent hosts google.com
You can also use:
nslookup google.com
If installed:
dig google.com
Install DNS tools
Ubuntu:
sudo apt install dnsutils
Then:
dig google.com
9. dig
Basic:
dig google.com
Short answer:
dig +short google.com
Check a specific DNS record:
dig google.com A
Check MX:
dig google.com MX
Check nameservers:
dig google.com NS
10. curl
curl is extremely useful for DevOps.
Test a website:
curl https://google.com
Show only HTTP headers:
curl -I https://google.com
Example:
HTTP/2 200
This tells you the HTTP server responded.
11. Test an Application Port
Suppose your application runs on:
8080
Test:
nc -zv 192.168.1.100 8080
Example successful output:
Connection to 192.168.1.100 8080 port [tcp/*] succeeded!
Install netcat if required:
sudo apt install netcat-openbsd
12. ss — Check Listening Ports
You learned this in SSH/security, but now we'll use it for troubleshooting.
ss -tuln
With processes:
sudo ss -tulnp
Example:
LISTEN 0 128 0.0.0.0:8080
This tells you something is listening on port 8080.
Only TCP listening ports
ss -ltn
Only UDP
ss -lun
13. Check a Specific Port
sudo ss -ltnp | grep :8080
If nothing appears:
No service is listening on 8080.
So if your application isn't accessible, the problem might be the application itself rather than the network.
14. Traceroute
traceroute shows the path packets take toward a destination.
Install:
sudo apt install traceroute
Run:
traceroute google.com
You can also use:
tracepath google.com
If traceroute isn't working on your Ubuntu system, try:
tracepath google.com
This is useful for identifying where network traffic is failing or experiencing delays.
15. hostname
Show hostname:
hostname
Detailed:
hostnamectl
Change hostname:
sudo hostnamectl set-hostname myserver
Check:
hostname
16. /etc/hosts
Local hostname mappings are stored in:
/etc/hosts
View:
cat /etc/hosts
Example:
127.0.0.1 localhost
192.168.1.100 myserver
You can test:
ping myserver
The system can resolve myserver using /etc/hosts.
17. DNS Configuration
On modern Ubuntu systems using systemd-resolved, check:
resolvectl status
You can also inspect:
cat /etc/resolv.conf
Look for DNS configuration.
18. NetworkManager
On Ubuntu desktop installations, NetworkManager is commonly used.
Check:
nmcli device status
Example:
DEVICE   TYPE      STATE
eth0     ethernet  connected
lo       loopback  connected
Show connections:
nmcli connection show
Show detailed device information:
nmcli device show
19. Check Network Service
Depending on your Ubuntu configuration, networking may be managed by NetworkManager or systemd-networkd/netplan.
Check:
systemctl status NetworkManager
Check network configuration files:
ls /etc/netplan/
View:
cat /etc/netplan/*.yaml
⚠️ Don't edit network configuration blindly, especially on remote servers.
20. Network Statistics
Show interface statistics:
ip -s link
This can help identify:
RX errors
TX errors
Dropped packets
Packets received
Packets transmitted
For example:
ip -s link show eth0
21. Check Open Connections
ss -tun
Show established TCP connections:
ss -tn state established
This is useful when investigating which servers/applications your machine is communicating with.
22. Check Firewall
For Ubuntu UFW:
sudo ufw status
Detailed:
sudo ufw status verbose
Remember:
Application
    ↓
Listening Port
    ↓
Firewall
    ↓
Network
A service can be running and listening but still be inaccessible because a firewall blocks it.
23. Network Troubleshooting Example 🚨
Imagine your Spring Boot application runs on:
192.168.1.100:8080
But you can't access it.
Step 1
Check server IP:
ip a
Step 2
Check route:
ip route
Step 3
Check application:
sudo systemctl status myapp
Step 4
Check port:
sudo ss -ltnp | grep :8080
Step 5
Test locally:
curl http://localhost:8080
Step 6
Test server IP:
curl http://192.168.1.100:8080
Step 7
Check firewall:
sudo ufw status
Step 8
From another machine:
nc -zv 192.168.1.100 8080
This gives you a systematic troubleshooting approach.

- Subnet
- Route table
- Internet Gateway/NAT
- Security Group

You've already been learning these AWS networking concepts, so this Linux topic connects them together.
